CCML — Stage 5.2: Traxsource resilient search

Why:
Traxsource currently presents Cloudflare / human-verification challenges to some
unattended HTTP clients. A raw HTML scraper can therefore return HTTP 403 even
though the catalog is public in a normal browser.

This stage DOES NOT emulate or defeat the Cloudflare challenge.

New behavior:
1. CCML tries the public Traxsource site directly, as before.
2. If direct lookup returns useful results, nothing else is called.
3. If direct lookup is blocked by Cloudflare/human verification, or returns no
   usable search results, CCML can call an optional structured JSON fallback.
4. The fallback API key is configured under Settings -> Traxsource.
5. If no fallback key is configured, CCML reports a compact actionable error
   instead of dumping a Cloudflare HTML page.

Current fallback:
Parse Traxsource API (independent third-party wrapper over public data)
https://parse.bot/marketplace/0123da1a-5d2d-4970-bf6f-398f792855a1/traxsource-com-api

The API service currently documents a free tier. Usage/pricing are controlled by
that third party and can change; CCML does not bundle or resell the service.

Environment variable alternative:
TRAXSOURCE_API_KEY

fallback for the Cloudflare/empty-result case.
