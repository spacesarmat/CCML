CCML — Stage 6: Parallel Metadata Enrichment

Goal:
Make "Дополнить выбранные" / "Enrich selected" substantially faster for a large
multi-track selection.

Current bottleneck:
CCML already queries different metadata providers concurrently for one track,
but the background queue processes selected tracks strictly one-by-one.

New execution model:

Before:
  Track 1 -> providers in parallel -> finish
  Track 2 -> providers in parallel -> finish
  Track 3 -> ...

After:
  Track 1 ┐
  Track 2 ├─ up to 4 tracks concurrently
  Track 3 ┤   and providers inside each track remain concurrent
  Track 4 ┘

Safety:
- bounded at 4 tracks, not unlimited goroutines
- MusicBrainz/iTunes/TheAudioDB provider rate limiters remain active
- persistent SQLite Jobs progress remains intact
- Pause cancels all currently running workers and requeues unfinished items
- Cancel cancels queued work and interrupts current workers
- successful items that finish at the same moment as Pause/Cancel remain successful
- app shutdown requeues in-flight work for the next launch
- Retry failed remains supported
- old Manager.Register callers remain serial and unchanged

Only metadata_enrichment opts into 4 workers.
